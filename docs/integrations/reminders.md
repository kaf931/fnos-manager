# 通知中心：记事与提醒

主菜单“通知中心”顶部横排展示通知模板，下方直接展示提醒事项，手机从“更多”进入。模板较多时在当前行横向滚动；点击模板编辑，更多菜单提供测试、编辑和删除，开关控制启用。模板操作不会筛选下方待办，待办搜索状态独立保留。新增或修改模板后，待办编辑器会同步刷新可选模板。

## 创建事项

在提醒事项中点击“新增事项”，填写名称和记事内容。保存前必须填写提醒时间，并选择至少一个已启用且配置完整的通知模板：

- 暂不启用提醒：仍需填写时间及选择可用模板，保存后不会调度通知。
- 启用提醒：到期时调度通知。符合选择条件的可用模板分别发送通知。
- 时间统一为北京时间，与计划任务一致。支持单次、每天、每周和每月；每周沿用首次日期的星期，每月沿用首次日期，目标月没有该日时取月末，下一月仍按原始日期计算。

“标记完成”会停止提醒并取消尚未发送的通知。“重新打开”恢复为待办，不自动启用旧提醒；可编辑时间后重新启用。需要调整提醒时间时，使用“编辑事项”。

## 通知与记录

提醒复用现有通知模板和发送队列。模板的任务结果条件用于任务通知，不会过滤手动选择模板的到期提醒。正在使用的模板需先从启用的提醒中移除或暂停提醒，才能停用或删除。

暂停后删除部分关联模板，重新启用提醒时会移除已删除的关联，使用剩余可用模板；仍存在但已停用的模板关联继续保留。全部关联模板都已删除时，会提示重新选择通知模板，事项内容保持不变。

模板消息可使用 `{{name}}`、`{{content}}`、`{{dueAt}}` 等变量。留空使用默认提醒内容；提醒时间变量按北京时间显示，Webhook 原始 JSON 保留带时区的 ISO 时间。记事正文不写运行日志。

投递记录仍在“存储管理 → 应用清理 → 投递记录”，沿用已有保留上限。一个提醒使用多个模板时分别记录结果；“已接收”表示渠道接收，不等同于设备已读。提醒本身为用户数据，不随历史记录清理；每账号最多保存500个事项，可自行删除。

NAS 重启后，错过的到期提醒补发一次；重复提醒直接计算未来的下一次，不逐条重放停机期间的所有周期。入队和推进时间位于同一数据库事务，防止重启或重复调度造成同一事件重复入队。提醒编辑、暂停、完成或删除会取消该事项尚未发送的通知；已经被渠道接收的消息无法撤回。

提醒也可选择“应用内通知”模板，在通知中心的消息列表接收。该模板必须先保存并启用；无需配置邮箱或外部推送地址。

## 状态与快捷配置

通知中心可见且未编辑事项时，每 15 秒同步提醒状态；页面从后台恢复时也会同步。页面隐藏或正在编辑事项时暂停同步，后台同步失败不重复打断编辑。

卡片显示待提醒、已暂停、已完成、模板不可用或已触发。“已触发”表示提醒已入队，不等同于消息送达；投递结果在投递记录中查看。

新增事项只有一个已启用且配置完整的模板时自动选中，仍可手动取消。没有可用模板时可直接点击“配置通知模板”；模板总览与编辑面板互斥，关闭模板面板后返回事项草稿，原名称、内容及时间保留。

新建事项默认勾选“启用提醒”，编辑已有事项保持原来的启用状态。临时清空时间输入不会改变启用选择，但保存时仍必须填写有效时间并选择可用模板。

## 批量管理与投递记录

顶部“批量管理”针对当前筛选列表，可批量标记完成、暂停或删除，每次最多 200 项。删除前确认，后端先校验全部事项归属，再在一个事务中执行；完成、暂停或删除会取消相关待发送通知，历史投递记录保留。

每张事项卡片提供“投递记录”，打开现有记录界面并按该事项筛选。通知模板的更多菜单也提供同类入口；提交测试通知后直接显示对应模板的投递记录，可刷新查看队列状态和错误原因。
