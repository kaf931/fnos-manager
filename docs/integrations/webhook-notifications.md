# 通知中心：通知模板

在 **通知中心 → 通知模板** 点击对应的未配置渠道卡片，填写名称与渠道配置，保存后在模板卡片的更多菜单点击“测试通知”。测试会发送真实消息，只使用已保存配置；模板停用时仍可测试。结果在 **存储管理 → 应用清理 → 投递记录** 查看。

桌面顶部默认展示八种内置渠道；移动端隐藏横向卡片及“通知模板”“提醒事项”标题，消息与全部入口合并到新增事项加号旁，通过“全部”打开公共底部面板查看和配置模板。超出宽度时在当前行横向滚动，两侧三角支持向左／向右翻动，到达对应边界后隐藏。两侧三角常态背景透明，悬浮时使用公共按钮高亮，不再预留空白轨道；横向滚动条复用公共 2px 样式，滚动时显示、停止后渐隐。鼠标位于模板行时，普通滚轮向下／向上分别向右／向左滚动；到达边界后交回页面处理，原生横向滚动、Shift+滚轮和 Ctrl／Command 缩放手势不拦截。模板区的“全部”打开公共大弹窗，以网格展示全部内置渠道及已配置模板；从总览进入编辑后，取消或保存均返回总览。未配置卡片点击后固定对应渠道并预填名称，表单不再提供渠道切换，保存前不会创建模板或发送通知；已配置渠道显示现有模板，支持同渠道创建多个模板。

每个账号最多创建 50 个通知模板，可分别启用并同时通知，支持通用 Webhook、企业微信、钉钉、飞书、SMTP 邮箱、Server酱、Bark 和应用内通知。切换渠道会清空编辑区里的旧地址、凭据和消息内容，保存前不影响已有模板；修改、停用或删除模板只取消该模板待处理的事件，不影响其他模板。历史投递记录保留，并显示模板名称。

## 渠道配置

| 渠道 | 必填配置 | 消息与鉴权 |
| --- | --- | --- |
| 通用 Webhook | HTTP(S) 地址 | 默认发送原结果 JSON；可选 Bearer Token、自定义 JSON 模板与 HMAC-SHA256 签名 |
| 企业微信 | 群机器人 Webhook 地址 | 文本消息；机器人 key 位于地址中 |
| 钉钉 | 自定义机器人 Webhook 地址 | 文本消息；可选加签密钥，机器人启用加签时必须填写 |
| 飞书 | 自定义机器人 Webhook 地址 | 文本消息；可选签名密钥，机器人启用签名校验时必须填写 |
| 邮箱（SMTP） | 主机、端口、发件与收件邮箱；按服务商要求填写账号和授权码 | 纯文本邮件，支持 TLS 和 STARTTLS |
| 个人微信（Server酱） | SendKey | SCT 使用 Turbo；sctp 自动选择 Server酱³，正文纯文本 |
| 手机推送（Bark） | Device Key、推送地址 | 默认官方地址，支持自建 Bark 服务，面向 iPhone |
| 应用内通知 | 名称、启用状态和通知条件 | 无需外部地址或凭据，消息保存到当前账号的应用内列表 |


钉钉／飞书机器人配置了关键词或 IP 规则时，消息内容与 NAS 出口也需要符合机器人设置。企业微信、钉钉、飞书按平台协议封装文本，不要求用户手写平台 JSON。

## 自定义消息与请求头

展开“自定义消息与请求头”。留空模板使用默认消息。

支持变量：`{{name}}`、`{{statusText}}`、`{{status}}`、`{{eventType}}`、`{{eventId}}`、`{{taskType}}`、`{{startedAt}}`、`{{finishedAt}}`、`{{exitCode}}`。`statusText` 为中文状态，时间为 ISO 8601 UTC；当前事件没有的字段替换为空字符串。不执行表达式、脚本或文件读取。

平台文本模板示例：

```text
NAS 管家：{{name}}
结果：{{statusText}}
完成时间：{{finishedAt}}
事件：{{eventId}}
```

通用 Webhook 模板必须是 JSON 对象，变量写在字符串值中，可嵌套对象和数组；替换后统一 JSON 序列化，名称里的引号不会破坏 JSON。示例：

```json
{"title":"NAS 管家","message":"{{name}}：{{statusText}}","eventId":"{{eventId}}"}
```

留空时，通用 Webhook 保持原来的事件 JSON，例如：

```json
{
  "eventId": "task:执行记录ID",
  "eventType": "task.result",
  "name": "夜间维护",
  "status": "success",
  "taskType": "script",
  "startedAt": "2026-10-23T01:00:00.000Z",
  "finishedAt": "2026-10-23T01:00:02.000Z",
  "exitCode": 0
}
```

自定义请求头使用 JSON 字符串键值对象，例如 `{"X-Api-Key":"your-key"}`。最多 20 项、总计 16 KiB；禁止 Host、Content-Type、Content-Length、连接控制和保留签名头。Bearer Token 与自定义 Authorization 不同时设置。地址不允许用户信息、片段或其他协议，不跟随重定向。

消息模板上限 8000 字符、JSON 嵌套最多 32 层；企业微信／钉钉文本最多 2048 UTF-8 字节、最终 JSON 最多 32 KiB，超限明确失败而不静默截断。

## 签名

签名在每次实际投递时重新计算，重试不会复用过期时间戳。

- **钉钉**：毫秒时间戳；`Base64(HMAC-SHA256(secret, timestamp + "\n" + secret))`，通过 URL 的 `timestamp` 和 `sign` 发送，参数由 URL 编码。
- **飞书**：秒时间戳；以 `timestamp + "\n" + secret` 为 HMAC 密钥，对空字节串计算 SHA256 并 Base64，写入正文的 `timestamp` 和 `sign`。
- **通用 Webhook**：秒时间戳通过 `X-NAS-Timestamp` 发送；`X-NAS-Signature` 为 `sha256=` 加上 `HMAC-SHA256(secret, timestamp + "." + 最终JSON原文字节)` 的十六进制摘要。接收端按原始请求体校验，并检查时间窗口及 eventId，防止重复处理。它是 NAS 管家定义的协议，不等同于任意服务的签名规范。
- 企业微信群机器人使用地址中的 key，不显示不适用的签名字段。

## 通知范围与投递

启用后可选“仅失败、超时或中断”或“全部执行结果”，另可选择扫描失败或中断时通知。共享计划任务发给开启通知的管理员配置，账号所属任务和扫描仅发给所属账号。普通成功扫描不发送；服务重启后未完成任务按中断规则通知。

事件为 `task.result`、`scan.failed`、`test`，仅包含结果摘要；扫描事件不包含路径，不发送脚本、终端输出、SSH 密码或 AI Key。

通用 Webhook 以 HTTP 2xx 为成功；内置渠道还校验平台响应中的 `errcode`、`code`／`StatusCode`。HTTP 200 但平台拒绝时记录固定原因和业务错误码，不保存远端错误原文、密钥或响应正文。

每次请求最多等待 10 秒。网络错误、HTTP 408／429／5xx 最多投递 3 次，分别等待 30 秒、120 秒；其他业务拒绝直接失败。响应读取最多 64 KiB。队列存入 SQLite，重启后恢复；网络异常可能造成重复消息，接收端可用 `eventId` 去重。通知失败不会重新执行原任务。

每账号最多 500 条进行中的投递。结束记录默认保留 200 条，上限在应用清理中配置。修改投递配置不会撤回已发出的消息，但不会向新渠道重试旧事件。

配置和记录按账号隔离。凭据沿用项目现有策略，保存在权限受限的 SQLite 中；界面凭据输入遮挡。通知配置不包含在配置备份中，恢复备份不会自动启用外发通知。

## 新增平台填写说明

通知中心已独立为主菜单，手机通过“更多 → 通知中心”进入；原系统设置入口已移除。首页顶部显示紧凑模板横排，下方显示提醒事项；模板使用公共卡片、启用开关与更多菜单；新增／编辑使用公共弹窗，保存按钮位于公共弹窗底栏；投递记录仍在应用清理中。

## SMTP 邮箱

点击“邮箱（SMTP）”未配置卡片，填写 SMTP 主机、端口、登录账号、授权码／密码、发件邮箱和收件邮箱。多个收件邮箱使用逗号分隔，最多 20 个；无需登录的本地邮件中继可留空账号和密码。

- 默认 STARTTLS／587，可选择 TLS／465 或显式“不加密”。按邮箱服务商提供的 SMTP 设置填写，使用 STARTTLS 时必须成功升级加密，TLS 默认验证证书。
- 邮件标题和消息内容支持同一套模板变量，留空使用默认内容。仅发送纯文本摘要，不读取附件、文件或远程 URL，不使用 HTTP 请求头。
- 全部收件人均被 SMTP 服务器接收后标记“已接收”，不表示已经进入收件箱。部分收件人被拒绝时明确失败，避免自动重试造成其他收件人重复收到。
- 认证、地址、TLS 或永久拒绝直接失败；临时连接问题沿用队列重试。投递记录仅保留固定分类与状态码，不保存服务器原始响应、授权码或邮件正文。

SMTP 传输使用 [Nodemailer 官方 SMTP transport](https://nodemailer.com/smtp)，邮件内容限制参考其[消息配置](https://nodemailer.com/message)。

记事、待办与定时提醒见 [提醒事项说明](reminders.md)。

已移除的渠道不再支持新建、启用或投递。旧配置与历史记录保留，待发送记录会取消；可编辑旧模板，重新填写支持的渠道配置后保存。

## 应用内消息

先点击“应用内通知”卡片配置并启用。任务结果、扫描失败和提醒到期按模板条件收集；不自动收集所有系统事件。

点击模板区右上角“消息”查看未读数量及记录，支持全部／未读筛选、查看详情自动已读、所选已读、全部已读和批量删除。桌面使用公共分页，小屏幕使用公共紧凑列表与加载更多。内容按纯文本展示，不执行 HTML 或脚本。

消息复用应用内渠道的成功投递记录，不增加另一套日志。保留数量与 **应用清理 → 配置 → 投递记录上限** 一致，默认 200 条（与其他渠道的投递记录合计）；在应用清理删除投递记录会同时移除对应消息。历史消息保留发送时正文，不会因后来修改模板而变化。消息与已读状态按账号隔离，未读数在通知中心打开时检查并每 15 秒刷新。

Server酱推荐入口：[获取 SendKey](https://sct.ftqq.com/r/29101)。支持 SCT 和 sctp 格式，平台受理成功不等于终端最终送达。Bark 支持官方或自建 `/push` 地址，不自动部署服务。

协议参考：[Server酱 Node.js 接入](https://sct.ftqq.com/docs/integrations/nodejs/)、[Bark API V2](https://github.com/Finb/bark-server/blob/master/docs/API_V2.md)。

桌面端消息入口位于左下角设置按钮右侧，点击展开最近五条消息菜单；未读消息带标记，点击查看详情并标为已读。“查看全部消息”进入完整消息管理。移动端消息入口暂保留在提醒工具栏。

通知中心顶部统一放置搜索、状态筛选、新增事项、全部模板和刷新入口；刷新同时更新模板及提醒列表，不再单独显示模板和提醒分区工具栏。桌面消息仍位于侧栏左下角，移动端消息并入顶部工具栏。

桌面消息菜单可直接“全部已读”。移动端收到应用内未读消息时，“更多”及其中的“通知中心”显示未读红点；应用更新仍在其自身菜单项显示独立提示。各消息入口共用同一未读数量轮询源，读消息或全部已读后同步刷新。模板入口文字为“全部模板”。
