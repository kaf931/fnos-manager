# GitHub 版本检查与一键更新

系统设置 → 关于应用 → 检查更新，从 `kaf931/fnos-manager` 的 GitHub Releases 获取最新正式版本、更新说明及本机架构安装包。后台启动约4秒后检测，此后每6小时检测；离线不弹错误。发现新版本时，桌面端左侧菜单底部、设置按钮左边出现强调色提示入口，点击打开更新弹窗；下载时显示实际百分比，之后显示安装阶段。移动端“更多”图标显示公共红点徽章，展开后“应用更新”文字后同样显示红点，点击直接打开更新弹窗；无新版时隐藏徽章和菜单入口。

## 发布约定

Release tag 使用 `v0.3.5` 或 `0.3.5`。草稿与预发布不参与更新检查。正文作为 Markdown 更新说明，附件按架构唯一：

- x86_64：`NAS管家-0.3.5-x86_64.fpk`（兼容现有无架构后缀名称）
- ARM64：`NAS管家-0.3.5-arm64.fpk`

自动安装要求 GitHub 附件元信息提供 SHA-256 digest；缺少校验值、架构不匹配或有多个候选时不自动安装。包内 manifest 的 appname 必须为 deskicons，版本必须与 tag 相符，架构必须与当前 NAS 相符；package.json 运行版本也必须一致。

## 更新方式

关于应用新增“更新方式”，默认手动更新。自动更新是本设备全局设置，仅管理员可修改；启用后后台发现新版将等待SSH/VNC/RDP连接、运行任务、扫描/文件操作和AI执行结束，再下载和安装。下载后会再次核对空闲状态，最终校验时阻止新写请求；等待最长30分钟。关闭自动更新会取消尚未进入安装的任务。自动失败后至少间隔6小时重试同一版本，避免反复重启。

## 更新流程

当前已是最新版本时按钮禁用，不重装或降级。有新版时管理员点击“立即更新”，NAS 下载文件并显示实际已传输字节和百分比，完成 SHA-256 校验及受限解包，再由独立更新进程停止服务、备份 SQLite 和旧运行文件、替换运行文件并重启。新版本需通过运行版本、关键接口、配置数量和 SQLite 完整性检查；失败时恢复旧运行文件与 SQLite。成功后页面自动刷新，亦提供刷新按钮。窗口关闭不停止后台任务，重新打开可查看进度。

这是应用内**运行文件更新**，不执行卸载、不清空数据、不调用 appcenter-cli install-local，也不修改应用中心登记版本。保留现有 cmd/config/wizard/资源登记；涉及这些安装元信息变更的版本应走人工验证后的安装流程。

需要原生 Linux NAS 运行环境、可访问 GitHub、Python 3.9+，运行目录和数据目录须在同一文件系统。下载超时10分钟，安装包最大512MiB、解包最大2GiB。更新前检查可用空间。下载及解包失败不会停止服务。替换/验收期间暂时拒绝应用写请求，远程连接会断开。

## 断点续传

下载中断后保留未完成文件及来源URL、总大小、SHA-256、ETag/Last-Modified。重试同一版本和同一附件时继承已有字节，用Range和If-Range继续；应用重启后也可重试。服务器不支持Range、校验实体变化或返回416时重新下载；无效Content-Range不追加，完整SHA-256失败会删除损坏缓存。已下载完整且校验通过的包无需重复请求。桌面左下角设置旁的更新入口显示实际百分比，之后显示校验、安装和重启阶段，不显示旋转动画。

## 状态、缓存与回滚

任务状态和诊断日志位于应用数据目录 `updates/<任务ID>/status.json`、`update.log`；`current.json` 指向最近一次任务。最近一次任务保留旧运行文件及数据库快照，下次更新时清理前一次任务，不累积多份缓存。勿在更新中手动删除此目录。

回滚已通过隔离模拟服务验证；没有用正式NAS已发布的同版本旧包覆盖当前开发代码。断电、系统故障及安装元信息变更不属于现有自动验收覆盖范围。若进程或系统在替换中被强制终止且应用无法启动，保留 updates 内快照，通过 SSH 恢复。

下载遇到连接/响应超时、临时网络中断、HTTP 408/429/5xx 时自动重试最多5次，间隔为2、4、8、16、30秒；每次重新读取已校验来源的断点文件。状态及update.log记录重试原因、次数。权限错误、来源/范围/大小异常及SHA-256失败不自动重试。直连出现临时网络错误后自动切换至已实测的镜像加速，后续重试交替使用直连/加速线路；仅加速安装包下载，版本及SHA-256仍来自官方API。

## 应用清理中的更新缓存

存储管理 → 应用清理 → 更新缓存可查看任务、实际占用和更新日志，沿用公共列表、分页与批量管理。可清理已结束且工作进程已退出的任务，包括断点包、解包目录、日志、旧运行文件和回滚数据库快照。清理后无法继续该断点或使用该任务的回滚备份；正在下载、等待安装、安装或重启验证的任务受保护。清理与新建更新任务互斥，不跟随目录内的软链接，不涉及当前运行文件及应用数据。

安装前识别目标包数据库schema；目标低于当前数据库时直接拒绝，提示两个schema版本，不停止服务。启动验收错误记录关键接口、预期/实际版本，回滚后保留具体错误原因。更新弹窗标明任务版本，旧失败任务不阻挡新版，支持重新检查；打开时每30秒及窗口获得焦点时刷新发布信息。GitHub暂不可达时保留上次检查结果并标记。

## 2026-11-04 下载线路与停止更新

设置 → 关于应用 → 下载线路，可选 GitHub直连、镜像加速；该设置决定优先尝试哪条安装包下载线路。默认直连，失败时仍切换另一条线路并保留重试、断点续传、重定向白名单和官方SHA-256校验。版本及发布信息仍从GitHub官方API获取。线路设置与手动/自动更新独立，存入SQLite，重启后保留；每个新任务保存其启动时的线路选择。

下载、校验、等待空闲时，弹窗提供“停止更新”；停止后保留可续传缓存。服务器先校验记录与真实进程身份，暂停指定独立更新进程组后复查任务状态和安装锁，确认尚未进入安装才终止；若已进入安装则恢复进程并拒绝停止，避免破坏运行文件或数据库。安装阶段不提供强制停止。旧更新进程也按相同安全边界处理，不依赖旧worker支持新消息。

任务启动后使用固定的发布快照，删除发布不一定会立刻切断已建立下载连接。任务与最新发布不一致时，弹窗不再混入其他版本的说明。安装前重新通过官方tag API核对发布及附件URL、大小、摘要；发布撤回、转为草稿或附件变化时取消安装并保留缓存。无法确认发布有效时不进入安装，保留错误供重试。
