# 完整 Skills 包导入、资源读取与 SSH 执行

状态：供用户审阅；尚未修改产品代码或部署。2026-10-22。

## 用户目标与范围

用户要求补齐当前 AI 的缺失能力，能够下载或导入官方 Skills ZIP，按原始文档使用配套资源、脚本及 CLI，并完成官方浏览器授权。保留已有单文件技能、聊天、附件、审核和静默功能，界面全部复用公共组件。

本设计替代 ai-fnos-tools-design 中的专用操作目录。采用通用完整包支持，附加飞牛官方授权辅助表单；不会重新实现官方 CLI 的文件、Docker、应用等业务接口。第一版仍在当前已连接 SSH 会话中使用 AI，执行目标为该 SSH 主机，不新增脱离 SSH 的独立 AI 执行器，也不以 NAS 管家后端服务权限直接运行第三方脚本。

## 方案选择

推荐完整包保存、按需读取、通过当前 SSH 执行：保持官方内容和版本关系，继续使用当前命令审核。仅上传 ZIP 当普通聊天附件无法提供可靠资源寻址；改写专用工具目录则会重复维护官方业务接口。因此不采用后两者。

### 导入与管理

现有技能管理增加 ZIP 上传、HTTPS 地址导入，以及固定版本的“飞牛官方 Skills”快捷导入。继续支持单 SKILL.md；本轮不自动订阅更新、不运行导入钩子、不做技能市场。

导入先展示名称、描述、来源、摘要、文件数及包含脚本的信息，确认保存后默认禁用。一个 ZIP 必须包含唯一 SKILL.md；允许直接根目录或单层包目录，多个技能的集合要求用户分别导入。原始文件保持原样，包括启动脚本、资源路径和运行时清单，不能格式化或改写导致摘要失效。

包技能正文只读展示，更新用重新导入整包替换；单文件技能保留现有编辑功能。替换保留技能 ID，增加修订号，显式确认后生效；不自动执行新版本。启用不等于执行，allowed-tools 不改变用户审核模式。

HTTPS 导入最多 3 次重定向，每跳重新校验地址和解析 IP，拒绝凭据、非 HTTPS、环回、私网、链路本地及云元数据地址；不发送应用 Cookie 或 Authorization。20 秒超时、压缩包最大 10 MiB；不允许解压后再决定限额。官方快捷入口使用固定版本地址及已核验摘要，自定义来源显示实算摘要但不伪称官方认证。

ZIP 限制：最多 512 条目、总展开 32 MiB、单文件 4 MiB；SKILL.md 仍受 64 KiB 限制。拒绝绝对路径、盘符、反斜线、空字节、上级路径、符号链接、加密条目、重复规范路径、文件/目录冲突和损坏 CRC。流式读取同时计数，防止虚假大小绕过；失败清理临时目录，不能留下可启用半包。

### 数据与文件生命周期

技能定义和配置继续 SQLite；包文件保存应用数据目录，不把 ZIP 和二进制大块塞进数据库。schema11 增量迁移：ai_skills 增加 kind、revision、package_id；新增 STRICT ai_skill_packages 与 ai_skill_package_files，包含 owner、摘要、来源、相对路径、大小和文件摘要，必要外键、唯一约束及索引。原单文件技能映射 document 类型，不丢弃或复制旧数据。

包路径由服务端 ID 生成，按账号/技能/修订存放；目录 0700、文件 0600，只有显式执行准备才赋予已选脚本执行权限。写文件暂存后原子提交，再在事务中切换修订；崩溃产生的未引用暂存文件可清理。删除或替换包先停止本账号引用该版本的待执行提案，活跃执行持有版本引用，排空后回收。服务启动处理孤儿临时文件。

数据库仅存相对路径，不接受客户端指定磁盘位置。备份、卸载保留/删除沿用应用数据策略。存储管理“应用附件”不混入技能包；技能管理自己展示包占用及删除入口，避免附件清理误删正在启用的技能。

### 渐进读取

read_skill 返回正文和受限文件索引，不一次注入全部文档。增加 list_skill_resources 与 read_skill_resource，按技能名、修订及相对路径读取。每次都校验账号、启用状态、包归属、路径和文件摘要；只能读取已登记资源，禁止链接穿越和任意本地路径。

文本工具单次最多 64 KiB，支持按偏移分页并返回截断标记；拒绝二进制作为文本、限制每轮读取总量 256 KiB。返回包内规范路径和版本，资源内容视为技能数据，不能覆盖系统指令、授予权限或改变目标。图片等二进制可在管理器下载查看，本轮不向模型自动发送包内所有资产。

OpenAI 兼容、Claude、Gemini、Ollama统一声明、校验、工具结果配对和历史恢复。同一轮绑定不可变版本；编辑/替换后新一轮加载新版本，旧提案执行前复核版本，失效时明确要求重新生成。

### SSH 运行环境

新增 prepare_skill_runtime 工具，生成现有提案区中的“准备技能运行环境”动作，展示 SSH 目标、技能版本、将上传的文件数/大小和远端目录。对已核验的官方飞牛包，同时明确展示将运行同包启动器 version、可能下载固定版本 CLI 及其缓存位置；通用包只上传，不自动运行未知初始化脚本。审核模式确认后才上传；静默模式仅沿用用户主动开启的本 SSH 会话设置。单纯 read_skill 不上传、不下载 CLI、不执行脚本。

通过当前连接的 SFTP 上传包到 SSH 用户 HOME 下服务端生成的 .local/share/nas-manager/skills/<owner-id>/<skill-id>/<digest>，使用临时目录和完成标记，验证摘要后发布；拒绝可疑链接或既有不匹配目录。远端目录权限 0700，不覆盖用户文件，不使用 sudo。文件系统权限与执行能力属于当前 SSH 用户；同一远端系统账号下的不同应用账号不能宣称操作系统级隔离。

第一版执行环境支持现有 POSIX SSH 主机；先检测平台、shell、可用摘要工具及包要求。不支持的环境清楚返回原因，Windows 脚本仍原样保存，但不声称本版能在 Windows SSH 上执行。只有准备成功才向模型返回绝对 Skill 根路径，模型随后通过现有 run_ssh_command 调用其中启动脚本。

原脚本的固定版本下载、摘要校验和缓存保持原样；官方 CLI 首次下载在已确认的准备动作中通过 version 触发，需要网络；该准备动作最多 120 秒且可取消，后续业务命令维持原 30 秒超时。通用包需要额外安装时由模型提出明确命令，遵循普通审核及超时，不能借包声明提升限制。缺少依赖时提示具体名称，不自动 sudo 安装软件。通用脚本在 SSH 用户权限下运行，并非安全沙箱；默认审核中展示实际执行命令。

取消、断线、关闭会话、重复确认和迟到结果沿用执行代次及排空机制。上传中断清理临时文件；已运行的远端业务不能承诺撤销。远端已发布缓存保留供下次复用，技能删除可提交清理动作，但不远程删除登录态或用户目录。

### 飞牛授权辅助

仅对内置固定来源且摘要通过的官方 fnos-cli 包提供“飞牛授权”辅助入口，不让任意第三方包冒充凭据收集表单。用户填写 NAS 地址，界面明确显示当前 SSH 执行主机及目标 NAS；两者可能不同。

应用调用同包启动器的两段式 OAuth：authorize-only 得到官方链接，由用户打开浏览器登录、选择权限并完成访问码/2FA；授权码粘贴专用表单，再在相同 SSH 主机、系统用户、profile、配置目录和目标参数下兑换。成功必须验证 token_persisted、refresh_token_persisted 并执行 system info。pending 有效期按官方 5 分钟，未过期不重复覆盖；失败不循环消费授权码。

按应用账号、SSH 连接配置及 NAS 目标生成独立 profile 和远端私有配置目录。连接元数据使用新增 STRICT ai_skill_authorizations 表；不复用计划任务全局授权。OAuth session、PKCE 与 token 留在官方 CLI 的受控存储，不读给模型，不进入 SQLite 聊天或日志。文件回退由用户在表单中明确选择，不静默降低存储方式。

授权表单请求有账号、当前 SSH 会话及 CSRF 校验。一次性 code 只通过后端专用短暂请求传给官方 CLI，正确逐参数 shell 引用，关闭/成功即清空，不写对话、提案、日志；远端进程参数可能短暂可见，不承诺完全不可观察。模型只收到是否已授权和非敏感目标标识。

生成、兑换、断开按 profile 串行；目标改变使 pending 和待执行提案失效。退出清理本地 profile 不等于撤销 NAS 远端授权，界面沿用官方说明。授权辅助不是新的业务操作协议，后续操作仍由原 Skill 指导调用 CLI，通过现有 SSH 命令审核执行。

## 模块和界面

- domain 明确区分单文件与包技能、只读资源调用、运行准备提案，禁止字符串猜测动作类型。
- skill-package-importer 负责下载、ZIP 验证和暂存；package-store 负责文件生命周期；repository 负责 SQL。
- skill-resources 负责受限读取；skill-runtime 负责 SFTP 准备和环境检测；fnos-skill-auth 仅负责原 CLI OAuth 编排。
- conversation 复用工具回合、审核与取消，仅调用上述接口，不引入解压、SQL 或授权表单处理。
- Nest 注册显式导入、资源、运行准备及授权端点，统一管理员网关、owner 和 CSRF；所有错误返回可理解状态。
- 复用现有技能管理、Tooltip、下拉、导入控件、提案卡片、滚动条和移动底部面板；显示进度、重试及失败原因，不新增平行样式。

## 验收与部署

1. 使用官方 ZIP 夹具验证导入、摘要、完整资源和脚本内容保真；畸形包、ZIP 炸弹、路径、SSRF、重复文件、清理及账号隔离回归。
2. schema11 升级保留单文件技能和全部业务数据；删除/替换/重启一致性、外键与完整性通过。
3. 四协议按需资源调用、截断、版本变更、历史恢复、审核等待、静默、并发取消、SFTP 半上传和断线回归。
4. OAuth 夹具验证同环境绑定、一次性码不入聊天、pending 过期、刷新失败、权限错误及计划任务授权不受影响。
5. 浏览器检查桌面/390px 的导入、文件树/资源查看、进度、授权和提案；不能只做静态截图。
6. 全量测试、strict 类型/AST、lint、格式及 FPK 构建通过后，按既有 SSH 停止→替换→启动部署，保留数据，核对运行版本、服务、数据库和关键接口并记录。不得走应用中心升级。
7. NAS 真机用隔离测试包验证资源读取、运行时准备、version/help，不运行破坏操作。真实官方 OAuth 需用户自行授权，未完成前明确记录“未验证真实授权”，不得假称通过。
