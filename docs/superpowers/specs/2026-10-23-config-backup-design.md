# 配置备份与恢复设计

## 目的与已确认选择

用户希望完善已有功能，先支持在重装或迁移 NAS 时恢复配置。用户已明确选择：合并导入，先预览冲突后处理；不自动覆盖，也不自动启用任务。界面放在系统设置，使用公共样式。

## 方案比较

- 整库替换：包括历史和全部账号，但会覆盖当前数据、运行状态和账号归属，不符合用户选择，排除。
- 版本化配置包合并：仅导出明确允许的配置，通过类型验证及关联重映射导入，可预览冲突。采用此方案。
- 逐菜单单独导出：接口简单，但容易丢失 SSH、设备、任务间的关联，不作为主方案。

## 范围

导出选项包括：全局桌面图标及图像；当前用户可管理的计划任务；当前账号 SSH 资产目录、连接、快捷指令目录与内容、常用命令、网络唤醒设备、AI 供应商和使用偏好。

凭据为单独选项，默认不勾选，含 SSH 密码/私钥/口令和 AI API Key。按照已有用户要求不强制加密，导出前明确显示是否包含凭据。任务脚本、快捷指令中可能包含用户自行填写的秘密，不能声称不勾选凭据就不含任何敏感数据。

第一版配置包不包含执行历史、聊天、聊天附件、扫描结果、改名记录、技能包内容、官方授权令牌、主机信任记录、活动连接、文件传输状态以及 NAS 实际文件。导出界面明确范围；不称为完整系统备份。技能包仍用现有管理能力。

## 文件与格式

采用带 format/version/exportedAt/appVersion 的 JSON 配置包；图标使用受大小限制的 base64 图像。配置包是用户下载的交换文件，不是应用新增的持久存储方式。应用实际数据继续存入 SQLite。

后端建立明确 DTO/领域导入类型；严格限制文件大小、每种实体数量、字符串长度、图片类型和解码大小。拒绝未知格式版本、重复 ID、错误枚举、悬空关联、目录循环及非法字段。禁止执行导入文件中的代码、SQL、路径或网络请求。所有 ID 和拥有者均由服务端重映射，不能通过包里的 owner 字段写入其他账号。

## 导出一致性

在同一个短只读事务中读取选择的配置与关联。仅导出当前身份能访问的对象。图标是现有全局管理员配置；私人 SSH/设备/AI/命令/偏好限定当前账号；任务按现有授权模型筛选。所选任务引用设备时，导出纳入所需设备及 SSH 配置或提示补选，不能生成断开的关系。

## 恢复流程

1. 点击恢复，选择文件，服务器验证格式与内容，返回各模块数量、冲突项、依赖项和跳过原因。
2. 同名配置默认跳过；用户可选择作为新副本导入并重命名。第一版不覆盖现有对象。偏好属于单例，明确选择是否应用；默认保留当前偏好。
3. 依赖被跳过时，需要将引用映射到明确选定的已有兼容对象；否则依赖它的条目禁止导入，并给出原因。不能仅凭同名静默绑定。
4. 点击确认后，服务端重新验证包和当前配置。预览后现有数据发生变化则要求刷新预览，避免沿用过期冲突决定。
5. 在一个数据库事务中按目录、连接、设备、任务等依赖顺序创建对象；失败整体回滚。导入结束显示成功/跳过数量并刷新菜单数据。

恢复任务一律暂停、清空下次执行时间；设备电源任务不继承之前的确认快照，需按现有流程重新核对目标。图标安装状态清空，用户重新添加到桌面；不自动安装入口。Docker 容器标识、NAS 本地路径可能在新设备上失效，预览标为需核对，不声称自动迁移容器或文件。首次 SSH 连接重新确认主机指纹。

不影响已连接会话，不替换运行数据库，不重启服务，不删除现有配置或实际文件。

## 代码边界

新增配置备份 Nest 模块、DTO、应用服务，以及负责事务读取/合并写入的仓库。复用现有领域验证规则，避免绕过任务校验和账号隔离。前端增加系统设置的数据管理区，备份/恢复共用公共弹窗，恢复预览使用公共表格。

## 验收

- 有/无凭据导出，不能泄露其他账号配置；恢复到不同账号后归属正确。
- 图像、目录树、SSH→设备→任务及指令目录关系完整。
- 同名、同 ID、非法格式、超限、悬空引用、目录循环和重复提交处理正确。
- 预览后配置变化不误覆盖；失败不留下半批导入；当前数据不变。
- 任务暂停、图标未安装、主机指纹不继承、无网络/命令执行副作用。
- 公共界面样式、取消行为、移动端操作可用；导入/导出失败有明确反馈。
- 类型、lint、格式、相关回归及完整构建通过后，SSH 更新 NAS，确认数据库完整性及关键接口。真机验收只使用临时配置，不恢复覆盖真实配置。

## 审查补充：待完善配置与幂等

- 不含凭据的 SSH 连接同时清空 authMethod 和 credentials，保留主机/端口/用户名，界面标为未保存认证。不能构造一个带认证方式但无凭据的新增请求绕过现有校验。首次连接须补填认证信息。
- 导入的设备电源任务以及需要重新授权/确认目标的任务引入明确的待完善状态，显示原因。导入验证允许存储完整的任务意图，但不生成可直接执行的确认信息；启用、立即执行、调度三处均拒绝待完善任务。只有走现有编辑和目标确认流程后才能清除状态。对应字段通过版本化 SQLite 迁移加入，不能把 enabled=false 当作唯一执行门禁。
- 预览返回当前配置摘要、包摘要及短期有效的预览凭证；提交时核对当前账号、包摘要、用户选择和配置摘要。摘要不向前端暴露明文凭据。发生变化返回409，要求重新预览。
- 导入提交携带随机请求ID；在同一个导入事务中持久化请求ID、包/选择摘要及导入结果。相同账号与请求ID的同内容重复提交返回原结果，不创建重复配置；同ID不同内容拒绝。服务重启和网络重试不丢失幂等保护。后续统一操作记录可关联该导入结果。
- 第一版不提供同名覆盖操作；文件名及对象名称用于展示，不作为文件系统路径。每个导入对象使用服务端新ID，目录层级保留，关联对象使用ID映射，不依赖名称猜测。

## 审查补充：冲突与现有约束

- 非设备计划任务按现有实现为管理员共享，设备任务按账号隔离；导入不改变该权限模型。图标也属全局配置。所有映射候选均重新按当前身份过滤。
- 目录冲突键为 scope＋映射后父目录＋名称；常用命令按 command 文本判断，不能通过改描述绕过唯一约束。同名连接、设备、供应商、图标、任务在预览中明确列出。包内冲突、改名后的新冲突均重新验证；跳过目录时必须选择现有同scope目录或连同子项跳过；多项导入对象不允许隐式合并到一个现有对象。
- 除包本身限额，合并后的对象总数、字段长度、目录深度严格沿用现有服务限额。目录深度最高16层。具体数值从服务常量共享，不在导入器维护第二套。
- 本机连接会连接目标NAS，预览明确提示；使用现有local规范化。导入常用命令前创建缺失的偏好行，但不覆盖现有偏好，保持命令目录初始化标志语义一致。
- 配置摘要只包含相关配置与凭据摘要，不含任务运行历史、唤醒时间等频繁变化的运行数据。数据库事务内只做同步查询与写入，异步解码/校验在事务外完成，提交时重核对。
- 后续Webhook配置加入配置包时需要提升格式版本或明确的向后兼容字段；URL中的令牌、签名密钥属于凭据，导入默认禁用通知，不能因恢复主动发消息。Webhook详细设计在第二项开始前完成。
