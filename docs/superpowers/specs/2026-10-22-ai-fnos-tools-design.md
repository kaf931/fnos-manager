# 内置 AI 接入飞牛官方授权与工具

状态：已被完整 Skills 包方案替代，不实施本文的专用操作目录。参见 [完整 Skills 包设计](2026-10-22-complete-skill-packages-design.md)。日期：2026-10-22。

## 目标和使用方式

在现有 AI 中，通过自然语言调用飞牛官方授权能力，完成文件、应用和 Docker 管理及系统查询。SSH 和官方 NAS 是两个明确的执行目标；官方操作由 NAS 管家后端调用随包 CLI，不依赖 SSH shell，不要求用户安装 Codex/Claude Code，也不要求上传官方 ZIP 才能使用。

用户在系统设置中新增「飞牛授权」配置入口；AI 头部的设置入口也可打开同一面板。用户指定 NAS 地址后生成官方链接，浏览器登录并勾选权限，把一次性授权码粘贴到专用表单完成连接。密码、2FA、访问码及授权确认由用户自行完成。授权码不进入 AI 输入框或对话历史，前端成功或关闭后清空；后端不记录它或令牌。

AI 的目标选择显示「当前 SSH」及「飞牛 NAS · 已授权地址」。更换目标开启新会话并恢复默认审核，避免把对一台设备的指令用于另一台。现有 SSH AI 保留原有连接逻辑。没有 SSH 连接时，系统设置的飞牛授权入口提供「打开 AI」，进入复用聊天组件的全覆盖 NAS AI 视图；不会为它建立假 SSH 连接或显示无效终端/文件监控功能。此视图提供返回、模型、历史、Skills、附件和审核控件，采用公共布局。

## 已核对的依据

- [飞牛授权说明](https://help.fnnas.com/articles/v1/settings/authorize)：最低 fnOS 1.2.0800；浏览器选权限，授权码有效流程；可在授权管理中调整及撤销。
- [官方 Skills 仓库](https://github.com/fnnas-labs/fnos-cli-skill)：官方 CLI 与 Skill 版本匹配；浏览器授权后使用相同目标、profile及配置环境兑换并验证。
- [官方 OAuth 参考](https://github.com/fnnas-labs/fnos-cli-skill/blob/main/skills/fnos-cli/reference/oauth.md)：PKCE、5分钟授权码、存储验证、刷新和撤销语义。
- 本项目随包 CLI 实测 `fnos-cli 0.5.0`，build source SHA256 `53829e556e9abcc84a074bfaa6100579d40927f2520af2e73826d170820518a7`；已在本机只运行 version/help，没有实际登录。
- 本项目现有 AI 只有 run_ssh_command/read_skill；计划任务的 OfficialClient 已实现两阶段授权与 CLI 调用。其 official_connection/profile为应用全局，不能直接作为任意账号 AI 的凭据。

## 方案选择

采用「共享官方客户端实现 + AI按账号独立授权 + 结构化操作目录」。不让模型通过 SSH 调用任意 fnos-cli，也不把全局计划任务授权自动暴露给其他管理员。继续使用已审阅和固定版本的随包 CLI；不在运行时下载 latest，不执行 Skills ZIP 里的安装脚本。

复用现有授权协议、子进程执行器及公共授权表单；抽出可注入的客户端与配置存储接口，使计划任务保持自己的现有授权，AI使用自己的账号记录和配置目录。此轮不迁移、删除或撤销计划任务已有登录态。以后若统一授权，必须先解决历史全局授权的归属，不能猜测绑定给第一个打开 AI 的账号。

## 授权数据与生命周期

schema11→12，新增 STRICT ai_fnos_connections：UUID主键、owner_uid唯一、origin、profile、授权状态、可选受限文件存储选择、pending_at、authorization_url、grant_revision及创建/更新时间。状态约束、唯一性及查询字段使用SQL约束，配置落SQLite。

官方CLI管理的PKCE及token session继续由官方存储机制保存，应用仅保存连接元数据。配置目录使用服务端生成的UUID，不能由模型或前端自由指定。文件存储回退须用户明确选中，沿用现有界面，不静默降低存储方式。目录0700；API不返回本地路径、token或PKCE内容。卸载保留/删除沿用应用数据策略。

生成链接、兑换和断开按账号串行；pending未过期不覆盖；超时、关闭、服务停止及重复点击均有取消/去重处理。撤销或切换授权增加grant_revision，未执行提案失效；执行前再次检查所属账号、目标和授权代次。CLI退出登录仅表示本地连接清理，UI提示可到飞牛授权管理撤销远端授权。

后端使用已确认的目标地址，不从模型参数接受host/profile/TLS/config/env覆盖。HTTP、HTTPS和证书处理沿用明确连接设置，不自动跳过证书验证，不猜测未知远端地址。

## AI 工具和第一版操作范围

1. fnos_capabilities：返回当前目标的可用结构化操作、参数约束与说明，不返回凭据；不是任意命令帮助或任意URL请求。
2. run_fnos_operation：参数为operation、校验后的业务参数及explanation；在现有命令提案区显示目标、操作和参数，由当前审核/静默策略执行并回传结果。
3. read_skill继续按需加载用户技能；增加版本绑定的「飞牛官方工具指南」，描述实际支持的operation。指南和元信息可查看，不能授予权限或改变审核模式，不伪称已安装完整官方Skill包。

第一版明确覆盖：

- 系统：设备信息、版本、运行时间、CPU/内存/网络/磁盘/进程只读查询。
- 文件：目录列举、搜索、属性，新建目录、重命名、复制、移动、删除。所有路径按官方CLI实际语义验证，目标路径与行为在提案中显示。
- Docker：镜像/容器/Compose列表，容器状态及日志，启动、停止、重启已有容器和已有Compose项目。
- 应用：已安装列表、状态，启动、停止、重启已有应用。

实施时逐个使用随包CLI帮助校验具体参数，形成固定映射和测试夹具。不开放raw/request或任意argv；CLI的login/logout、token及目标配置只由授权服务控制。禁止模型借文件上传等参数读取后端任意本地文件；本轮不提供本地路径上传、直接下载到本地文件或输出带令牌的下载链接。

照片、下载、百度网盘、用户管理、存储格式化/扩容、应用安装升级卸载及电源操作暂不在此版操作目录；即便用户勾选了这些scope，也不代表本应用已实现对应功能。模型必须说明不支持，不能回退到raw或改用SSH绕过。后续可按同一目录机制扩展。

## 审核、上下文和取消

执行提案使用TypeScript判别联合：SSH命令与fnOS操作有独立类型、目标标识及校验，不以字符串猜测类型。默认审核，当前会话主动选择静默后才自动执行。权限不足时展示CLI的可理解错误，引导用户调整官方授权，不自动扩权或循环重登。

模型只能提出操作；固定的本地CLI路径、连接参数、账号profile及受控环境由后端注入，通过spawn传argv，无shell拼接。业务输出视为数据，错误与输出裁剪/脱敏后回传，保持现有轮次和长度限额。授权码、token、配置目录不进入prompt或提案历史。

官方调用与SSH调用均支持停止、超时和关闭排空；停止不能承诺撤销已被NAS接受的操作。撤销等待、重复确认、目标切换、迟到响应与历史恢复沿用现有代次校验，并为新类型增加回归。

四种底层协议统一声明、解析和配对新工具；兼容协议供应商沿用同一实现。原聊天可正常读取，旧待执行命令恢复为失效；官方历史只在所属账号和原目标连接下恢复。

## 模块与界面边界

- 独立OfficialModule导出客户端工厂及授权能力；TasksModule与TerminalModule注入依赖，不建立循环依赖，不把官方客户端挂到任意全局对象。
- ai/fnos-operation-catalog负责操作/参数定义；fnos-executor负责固定CLI参数与结果；conversation负责审批、工具轮次和聊天状态，不承载授权表单或SQL。
- 连接repository负责SQLite；CLI session仍由官方管理；单元测试注入进程执行器，不能在生产模块添加测试分支。
- 复用公共NativeSelect、密码/授权控件、按钮、Tooltip、弹窗/移动底部面板、间距与滚动条；不新增平行主题或组件样式体系。
- Nest显式注册授权状态、生成链接、兑换、断开、操作能力和NAS AI会话端点；沿用管理员网关、owner及CSRF校验。授权表单与聊天API职责分开。

## 验收和部署

- 先写失败回归，再实现：账号隔离、参数/目标注入拒绝、授权状态机/代次、凭据不进入上下文、四协议工具结果、审核/静默、取消和并发、历史恢复、schema12保留旧数据。
- 操作目录的每个映射与随包CLI实际help校对；用进程夹具验证具体argv，不执行真实破坏操作。
- 浏览器验证桌面/390px：授权表单、目标切换、无SSH进入NAS AI、审核提案和错误提示。
- 全量测试、strict/前端AST、lint、格式和原生FPK构建通过后，经SSH保留数据替换运行文件并验收版本、服务、数据库及关键接口，不用应用中心升级。
- 真机需用户完成官方浏览器授权；授权前只验证未连接及隔离夹具路径，不声称真实OAuth已通过。授权后只读验证system info及目录/容器/应用列表；写操作用专门临时对象且单独明确授权，不测试重启/关闭NAS或删除用户文件。
