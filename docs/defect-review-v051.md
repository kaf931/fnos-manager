# 0.2.51 AI与设备批次并发复查

日期：2026-10-22。基线0.2.50的374项测试、类型、lint、格式检查通过；本轮检查新的并发时序和异常路径。

## 已复现并修复的四类问题

1. AI切换终端后自动取消请求网络延迟，用户返回同一终端发送的新一轮对话会被旧取消打断。现每个SSH会话按序发送消息、操作与自动取消；当前会话在屏障未结束时禁止新操作，其他会话不受阻塞。实际派发前再次校验目标和销毁状态，未派发的旧消息/执行/新建操作不再发送；清理取消仍能有序完成。
2. AI供应商保存/删除期间关闭设置弹窗，服务端成功后原逻辑因弹窗序号变化跳过onSave，当前workspace继续使用旧模型列表。现存活workspace仍执行保存后同步，旧响应不写旧表单/关闭新弹窗；统一saving锁解除时仅按当前状态刷新。
3. AI忙碌时打开历史条目不可点击，忙碌结束后弹窗不重渲染而继续disabled。现AI状态渲染主动刷新历史条目就绪状态，恢复无需关闭重开。
4. 网络唤醒close仅关闭电源客户端和等待当时的写队列，没有中断/等待仍在运行的整批；后续设备可能继续发送或向已关闭数据库写入。现关闭标记、服务级AbortController、批次追踪共同控制，先取消并等待全部批次，再等待最新数据库写队列；拒绝关闭后的新增/修改/删除/唤醒/电源操作。调用者单独取消不会关闭整个服务。

## 回归

AI新增12项回归，最初5项及后续6项实际派发校验均在旧实现确认失败后修复；另含主界面驱动历史刷新集成测试。设备生命周期新增3项：关闭取消当前4工作者并跳过第5台、调用者取消隔离、电源批次等待在途清理后结束。测试均使用隔离DOM/临时数据库/模拟provider与设备发送器，不访问真实AI或执行真实电源命令。

严格类型、109前端源审计、ESLint、Prettier及FPK构建均通过；最终测试及NAS验收见backend-architecture.md的0.2.51记录。本轮结论限于可验证的场景，不能据此宣称全部外部环境零缺陷。

最终389项测试全部通过。设备电源批次测试的清理逻辑也确保即使未来出现取消回归，模拟在途任务仍能被释放，避免测试进程无限等待；对应lint/格式检查通过。
