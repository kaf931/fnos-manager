# 0.2.49 行为缺陷复查

日期：2026-10-22。以0.2.48为基线，重新运行类型、代码风格与测试检查，同时独立检查异步响应和编辑器生命周期。基线357项测试通过，但针对新的交互时序仍发现以下三个实际缺陷。

| 问题 | 触发与影响 | 修复 |
| --- | --- | --- |
| 任务目标被旧请求覆盖 | app请求等待时切换Docker，Docker先返回、app后返回，可能保存docker类型和app目标的错误组合 | 目标请求序号、编辑器序号和当前类型同时校验；加载/失败/空目标禁用保存，提交入口再次检查 |
| 旧保存响应影响新表单 | 保存请求等待时关闭并重开任务编辑器，旧成功响应关闭新编辑器，旧失败响应向新表单写错误 | 保存捕获编辑器序号；仅更新原编辑器，旧错误单独toast，busy结束后按当前目标状态重算 |
| 取消同名上传却提示成功 | 第一项或中间项文件重名，在名称弹窗取消后跳出队列，仍显示上传完成 | 将名称弹窗取消标记为上传取消，停止后续文件，保留已上传项并刷新列表 |

任务时序回归在旧实现下确认失败，修复后通过；上传取消新增两项回归，旧实现均错误提示“上传完成”，修复后均显示“上传已取消”。测试使用隔离JSDOM及模拟API，不连接真实主机、不执行系统电源操作、不修改用户文件。

审查未发现新的服务端DTO/用户隔离/SQLite约束问题，但这不是全部环境和交互时序的穷举，也不表示零缺陷。实体手机WebView、第三方供应商及真实SSH网络环境仍依赖持续实机反馈。

最终364项测试全部通过，strict、109文件AST审计、ESLint、Prettier及FPK构建通过。NAS部署记录见backend-architecture.md的0.2.49条目。
