# 通知中心模板可用性测试

## 范围与结果

检查八种内置渠道的配置、序列化、发送、平台回执和错误处理，共 48 项通知相关测试通过。新增 HTTP 渠道集成测试，使用真实通知仓库、工作队列及发送器，将六种 HTTP 模板实际投递到本地接收端；邮件另通过本地 SMTP 协议接收端验证。

| 渠道 | 本次验证 | 结果 |
| --- | --- | --- |
| 通用 Webhook | 保存、队列、HTTP POST、自定义请求头、签名与重定向拒绝 | 本地测试通过 |
| 企业微信 | 文本消息格式、真实 HTTP 投递、业务回执校验 | 本地协议模拟通过 |
| 钉钉 | 文本消息、时间戳及签名、平台拒绝响应处理 | 本地协议模拟通过 |
| 飞书 | 文本消息、时间戳及签名、平台业务回执 | 本地协议模拟通过 |
| 邮箱 | SMTP 文本邮件发送、配置校验、认证与证书错误分类 | 本地 SMTP 发送及模拟错误测试通过 |
| Server酱 | SendKey 派生地址、请求内容、业务回执 | 本地协议模拟通过 |
| Bark | Device Key、请求内容、业务回执 | 本地协议模拟通过 |
| 应用内通知 | 队列、消息列表、未读与已读、清理、账号隔离 | 本地测试及 NAS 实测通过 |

Server酱测试中，固定 HTTPS 平台地址的请求仅在测试进程内重定向到本地接收端，未将假 SendKey 发到真实平台。测试结束恢复 HTTPS 请求函数。平台成功回执来自本地模拟，不代表真实平台账号、网络、TLS 或终端收件已验收。

现有测试同时验证 HTTP 200 但平台拒绝时不会误判成功、临时错误重试、尝试次数上限、配置修改取消旧任务、模板与消息的账号隔离。

## NAS 实测

运行版本 0.4.2。测试前通过只读查询确认：所有账号均无已保存通知模板，投递记录为空。因此没有可用于真实外部推送的机器人地址、邮箱账号、SendKey 或 Device Key。

通过当前应用的正式 API，以当前账号创建仅用于自检的临时应用内模板，并执行：

1. 保存模板及完整性校验成功。
2. 提交测试，运行中的 NAS 工作队列首次投递即成功。
3. 消息出现在应用内列表，未读数增加 1。
4. 标为已读成功，未读数恢复。
5. 删除临时模板，并按该次投递的精确 ID 清理消息与投递记录。

测试前后对通知模板、投递记录、提醒事项和模板排序表进行行内容哈希比较，均一致。未修改原有提醒或其他配置。

## 尚未验收

外部七种渠道在 NAS 上的真实连接与最终收件，需要配置对应的实际凭据后才能验证。本次结果不应被表述为所有外部渠道均已真实送达。

本次没有修改应用运行代码，只新增集成测试及验收记录，不涉及运行版本或应用中心登记版本变化。
