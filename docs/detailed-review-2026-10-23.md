## 已确认问题

### P2：AI 供应商 API Key 的 null 输入穿过 DTO 后触发 500

`AiSettingsDto.apiKey` 使用 `IsOptional`，null 可跳过后续字符串校验；`AiSettingsService.saveProvider` 只判断 undefined，然后直接 trim。使用隔离临时数据库，经完整 Nest HTTP 接口提交 `apiKey:null`，确认返回 500 和通用内部错误。应对 null 明确定义语义（建议拒绝为 400），保持省略保留、空字符串清空的既定语义。未发现本次请求产生持久化写入。

位置：backend/app/terminal/ai.dto.ts:20；backend/terminal/ai/settings.ts:83。

### P2：移动端附件全选在超过 200 项后无法整批取消

移动列表通过“加载更多”累积数据，选择上限为 200。全选处理只截取前 200 项，勾选状态却要求所有已加载项均选中。组件使用 201 项数据复现：第一次点击后选中 200 项、表头未勾选；第二次点击仍选中 200 项。需要统一“本批全选”的状态和上限语义，并给达到上限的单项选择提供反馈。

位置：web/storage-attachments.tsx:251-255；同文件:119。

### P2：静态资源 no-store 阻止拆包后的持久缓存收益

GatewayAccess.headers 对所有响应设置 Cache-Control:no-store，包括经过鉴权后的带哈希 JS/CSS。完整 Nest 服务请求 React vendor 文件，确认 200、Cache-Control:no-store，虽然具有 ETag，浏览器不能按预期持久缓存文件。上轮拆包是有效的文件组织优化，但“可独立缓存”的收益尚未落实。建议区分 HTML、API、带哈希静态资源；凭据和用户数据仍保持 no-store，静态资源缓存应继续经过既有鉴权边界审查。

位置：backend/app/common/security.ts:44；backend/app/bootstrap.ts 的 express.static 注册。
