# 功能实现复查

本轮追踪界面请求到服务及持久层，重点检查任务执行并发、历史生命周期、设备目标绑定、文件改名与传输会话隔离。没有执行 NAS 或远程设备重启、关机，也没有删除真实业务文件。

## 已确认并修复

1. **执行中的任务仍可能被并发修改或删除。** TaskEngine 原先在进入写入队列前检查 running，等待队列期间另一请求可启动执行。现在在事务实际写入前再次检查任务是否存在及是否运行，冲突返回 409。
2. **已删除任务可能被旧编辑请求重新写回。** 更新使用 upsert，队列等待期间任务可能被另一请求删除。现在写入前重新查询，任务消失返回 404，不重建。
3. **历史清理可能误删长任务的运行记录。** 原先只按时间保留最近 100 条，另一任务连续运行可能挤掉仍在运行的记录。现在只裁剪已结束记录，额外保留正在执行的记录；任务结束后再清理。
4. **重启恢复只处理历史第一页。** 新增持久层 running 查询，启动时恢复所有遗留运行记录，而非只查看最近 100 条；恢复后按历史保留数量清理。

## 局域网扫描流程复查

新增三项可复现缺陷及回归：

- 扫描取消后 busy 状态原本等待旧请求返回才清除，导致不能立即重新扫描。现在关闭扫描释放界面状态，旧请求的返回和 finally 都不能改变新扫描。
- 添加设备成功后刷新列表失败，原本在 catch 内再次刷新；二次失败会成为未处理拒绝，且当前列表无法记住已保存设备。现在刷新仅尝试一次，错误显示在界面，已成功保存的设备在本次扫描结果中不可重复选择，部分添加成功仍有明确反馈。
- 组件销毁后，原本尚未结束的批量循环仍会提交后续设备。现在每次提交前后检查当前生命周期，销毁后不再启动后续写入；已经发出的请求不声称能撤回。dispose 也支持重复调用。
