# NAS 管家开发说明

桌面图标、计划任务、远程连接（SSH/VNC/RDP）、存储管理、网络唤醒，以及系统设置。前端使用 Vite、React 和 Semi Design，后端使用 NestJS、TypeScript、Express 适配器，持久数据统一存入 SQLite。

面向 fnOS 1.2.0800 及以上的 x86_64 设备，依赖飞牛 Node.js 22。另提供 ARM64 构建包，尚未经过 ARM 真机验收，构建方式与验证边界见 [ARM64 构建记录](releases/0.3.1-arm64.md)。开发者为 [kaf](https://github.com/kaf931/fnos-manager)，发布者为 [kaf](https://club.fnnas.com/home.php?mod=space&uid=91804)。

> **远程连接**：原 SSH 终端菜单现统一管理 SSH、VNC、RDP 与 ADB。VNC 使用内置 noVNC 客户端，无需 Docker；目标主机需启用 VNC。支持画面缩放、剪贴板、键鼠和移动端输入。详见 [VNC 使用说明](integrations/vnc.md) 和 [RDP 使用说明](integrations/rdp.md)。

## 本轮新增能力

当前版本 **0.4.2**。完整变更见 [更新日志](../CHANGELOG.md)。

本轮包含 VNC 远程桌面、配置备份恢复、消息通知、在线编辑恢复与应用清理等能力。具体验证范围见各功能文档；现有教程截图尚未覆盖全部新增功能。

- **在线编辑恢复：** 保存前显示差异，可保留修改前版本；历史版本先预览、载入草稿，再确认保存。每个文件最多 10 个版本，每账号最多 100 条/100 MiB，全应用最多 1000 条/1 GiB。正文保存在私有目录，SQLite 仅保存索引；按账号、连接和主机身份隔离。历史正文不进入配置导出。
- **扫描对比：** 在扫描记录选择同目录两次已完成空间扫描，对比已保存文件的新增、删除、大小变化与一级目录增长。不完整覆盖仅显示未确认变化，不将缺失直接认作删除。
- **SSH 诊断与传输队列：** 展示连接阶段；上传下载支持排队、取消和失败重试，记录仍随 SSH 会话关闭清空。重试从头传输，不宣称断点续传。
- **任务策略：** 手动执行先预览；仅设备唤醒、程序/容器启动和停止可设置最多两次失败重试，间隔 30 秒；超时和中断不重试。停机错过任务默认跳过，可为上述类型选择恢复后补跑一次。
- **查重与 AI：** 查重支持优先保留目录并查看处理预览；AI 显示当前步骤、耗时及停止请求反馈，停止不等于撤销已执行命令。

### 桌面图标

Docker 来源读取容器名称、映射 TCP 端口及图标信息。图标依次尝试容器标签（`net.unraid.docker.icon`、`homepage.icon`、`dash.icon`）、服务网页图标、favicon及默认图标，也可手动上传。未映射端口的容器需要手动填写地址；自动协议判断仅供参考。选择容器不会启动、停止或删除容器。

“NAS 管家”类型可将远程连接、计划任务、存储管理、网络唤醒、系统设置或桌面图标生成为独立入口。来源筛选与卡片标签显示“NAS 管家”，添加面板对应的类型按钮目前为“管家功能”。

创建步骤：桌面图标 → 添加图标 → 管家功能 → 选择功能 → 检查名称/上传图标 → 保存图标 → 添加到桌面。手机通过筛选行右侧 ＋ 打开添加面板。此类型自动生成内部地址、固定使用飞牛窗口，不需要填写网址或选择打开方式。

从独立入口打开后只显示目标菜单内容，不显示主侧栏或手机底部导航；SSH 入口仍需手动点击连接。入口共用主应用数据和配置，不改变主应用默认菜单，使用统一网关且不绑定固定内网 IP。入口包声明依赖 NAS 管家，主应用必须在同一台 NAS 上安装并运行，账号权限及功能授权要求保持不变。

图文操作说明见 [桌面图标教程](论坛分享/01-桌面图标教程.md)。

首次安装没有预置图标。保存后点击“添加到桌面”，生成并安装独立 `deskicon.<随机ID>` 原生入口；也可下载入口 FPK 手动安装。编辑后可更新入口，删除仅卸载该入口。入口安装依赖主应用；安装、更新及卸载状态以系统实际返回为准。

### 计划任务

统一采用中国时区，默认暂停，错过执行时间不补跑。支持超时中止和最近100条执行日志；最多同时执行两个任务。Bash 脚本通过标准输入传递，不放入命令行参数。

官方授权类任务根据当前授权状态显示可用性。系统缓存、飞牛备份和快照创建没有已核实的公开调用，因此未提供可执行的内置类型。网络唤醒任务复用设备配置和 SSH 绑定，执行电源操作前需确认目标；目标变化会拒绝执行并要求重新确认。

### SSH 工作区

支持本机与远程主机、密码或私钥认证。连接由 NAS 发起，终端按目标 SSH 账号权限运行；本机同样需要开启 SSH。首次连接需核对主机指纹，指纹变化需重新确认。打开主菜单不自动连接，点击连接或打开资产标签后使用已保存认证信息登录。

每位管理员最多8个活动会话，全局最多32个；配置、会话按账号隔离。切换菜单保留连接，关闭连接标签清除该会话的传输记录；应用重启会结束会话。长期任务可在目标主机使用 tmux 等工具。

资产与快捷指令可按目录分类。快捷指令发送时自动追加回车，多行内容发送前确认；常用命令支持搜索、分类、新增和右键编辑/删除。命令提示选择后只填入，不自动执行，是否启用可在设置中配置。

SFTP 文件面板支持目录浏览、上传下载、上传文件夹、新建、重命名、删除空目录/文件、目录大小计算、权限设置、压缩/解压和在线编辑。路径与 Shell 的 `cd` 独立，使用相同 SSH 账号权限。单文件上传最多256MiB，不覆盖已有文件；目标需要启用 SFTP。压缩、解压及权限操作还要求目标提供 Python 3，具有条目、深度、内容大小和执行时间限制。

在线编辑通过文件右键菜单打开，支持 10 MiB 以内的 UTF-8/BOM、UTF-16 文本，并可选择 GBK/GB18030。提供行号、高亮、查找替换和保存快捷键；保存前检查文件版本，使用远端 OpenSSH 原子重命名写回。断线后禁止保存，失败保留草稿；不支持二进制、符号链接或 Office 文档编辑。

系统监控通过独立只读 exec 通道采样 Linux `/proc`、`ip`、`ps`、`df` 等信息，不向交互终端输入监控命令。缺少命令或采样失败时显示空值，切换连接会停止旧目标采样。

AI 支持多个供应商、OpenAI/Claude/Ollama及 Gemini、GLM、MiniMax、DeepSeek、MiMo 适配。可配置地址、API Key和默认模型，获取模型列表并测试连接。聊天绑定当前 SSH 会话，默认逐条审核命令；主动选择静默后仅对当前会话自动执行。SSH 凭据及终端历史不会自动发送给 AI。聊天支持 Markdown，历史持久保存最近50个会话。

### 存储管理

空间分析统计文件逻辑大小，按设备和 inode 对硬链接去重；该数值不等于磁盘实际占用，不包含快照独占空间。查重先按大小筛选，再完整计算 SHA-256。原生版只允许管理员扫描 `/vol数字` 下的实际目录，避免跟随符号链接和跨挂载点扫描。

每个用户同时一个扫描，全局最多两个；扫描有条目、深度、时间和读取量上限，达到限制会显示扫描不完整。结果、扫描记录和改名记录存入 SQLite，重启保留；未完成扫描标记中断，不自动重启。

文件整理支持浏览子目录，导航以后退至所选根目录为边界。批量管理支持统一命名、替换、前后缀、序号与扩展名保留，先预览再执行，每批最多500项，执行前核对文件身份且不覆盖目标。改名记录支持符合条件时撤销。

重复文件可选定保留副本，批量移动其余副本到指定目录或删除。执行前重新核对文件身份和内容，每批最多100个副本；移动不覆盖同名目标，删除后本应用不能恢复。空间分析、扫描记录中的“删除记录”只删除扫描数据，不删除实际文件。

### 网络唤醒

通过 UDP 发送标准 Magic Packet（6字节FF + 16次目标MAC），默认端口9。目标需要开启 BIOS/网卡网络唤醒，广播可达性由网络决定。“已发送”代表数据包已提交，不能证明设备已开机。

设备可填写用于检测状态的局域网 IP，扫描添加时自动填入；留空时使用关联 SSH 的局域网 IPv4 地址。卡片显示在线、未响应或未知，悬浮查看检测时间。进入菜单或刷新时检测，唤醒包发送后在 5/15/30 秒有限复查，检测到在线后停止。未响应不代表已关机，超过两分钟的结果显示未知。检测不登录 SSH。

支持局域网设备扫描及每批最多50台唤醒、4路并发。关机/重启仅绑定当前账号已有的远程 SSH 连接，每批最多10台，支持 Linux、Windows、macOS；Linux/macOS 非 root 账号需有相应免密 sudo 权限。固定电源命令由后端选择，不要求目标安装本应用客户端。

### 统一操作记录

存储管理 → 应用清理提供按账号隔离的操作记录，可按类型和结果筛选；默认保留最近 1000 条，上限在应用清理中配置。覆盖文件删除/改名、配置恢复、设备电源及 AI 实际执行，不保存命令正文、输出或凭据。详见 [记录范围与结果含义](integrations/operation-records.md)。

### 通知中心

通知模板支持八种内置渠道（含 SMTP 邮箱），保存后启用，可用卡片开关停用；提醒事项支持记事、待办、单次／日／周／月、中国大陆法定工作日／节假日及自定义周几，可完成、暂停和重新打开。提醒沿用北京时间，投递记录、重试和清理统一管理。详见 [通知渠道与模板](integrations/webhook-notifications.md) 和 [记事与提醒](integrations/reminders.md)。

### 配置备份与恢复

在系统设置中选择“备份”或“恢复”。配置包可选择桌面图标、计划任务、SSH 资产和连接、快捷指令/常用命令、网络设备、AI 供应商及使用偏好；关联设备和 SSH 配置会随任务导出。默认不包含 SSH 密码、私钥、API Key；主动勾选后以明文包含。脚本或命令中自行填写的秘密不会自动删除，请妥善保管备份。

恢复先预览再合并，同名条目默认跳过，可重命名为新副本，目录、SSH 和设备可明确关联已有兼容对象。不会覆盖已有对象；使用偏好需单独选择应用。导入计划任务默认暂停，需要重新核对目标/授权的任务显示“待完善”，编辑确认前不能执行或启用。图标需重新添加到桌面；本机连接会指向恢复后的 NAS。

这是配置备份，不包含 NAS 实际文件、技能包内容、聊天及附件、扫描/改名/执行历史、主机信任和官方授权。记录和凭据仍由 SQLite 存储，JSON 仅用作用户下载的交换文件。恢复采用数据库事务和持久幂等回执，网络重试不会重复创建配置。

## 架构和目录

```text
backend/
  app/                 Nest 模块、控制器、应用服务、DTO、鉴权和生命周期
  domain/              领域类型及受约束的枚举
  persistence/         SQLite schema、迁移及参数绑定仓库
  terminal/            SSH/SFTP、监控、AI会话及供应商适配
  storage/             扫描、查重、改名、受限文件操作
  tasks/               调度、任务校验及执行器
web/
  styles/              按组件组织的公共及存储样式
  contracts/           API、会话、任务等领域契约
  ui/                  有类型的静态宿主和浏览器适配
  terminal-file-*.tsx   文件面板 React 组件
  *.ts / *.tsx         业务逻辑与 React 动态界面
  assets/              应用与扫描图片
scripts/               后端编译、原生包生成和依赖锁定
tests/                Node测试、HTTP/SQLite/交互回归
docs/                 架构、集成、部署记录及教程
```

`backend/` 是后端唯一源码；`server/` 是 TypeScript 编译产物。`web/` 构建为 `dist/`，原生包输出至 `build/deskicons/`。生成目录、依赖和本地 `data/` 不作为源码维护。`native-ui.css` 与 `storage.css` 是有序样式入口，具体规则位于 `web/styles/`；主题和滚动条继续共用语义变量。

控制器负责 HTTP 和参数接收，业务编排位于应用服务，数据库操作位于仓库。普通 JSON 使用 Nest 标准返回值；文件和流式传输保留 Express 响应。异步工厂 Provider 统一初始化依赖，关闭流程先停止后台任务、传输和扫描，再关闭数据库。

## 数据与权限

数据目录使用飞牛 `TRIM_PKGVAR`，核心数据库为 `nas-manager.sqlite`，schema v32。图标、任务及日志、SSH 配置/凭据、工作区、常用命令、AI供应商/聊天、存储记录、设备和偏好均使用 SQLite。活动连接、执行中的任务对象、传输进度等临时运行状态保存在内存。文件传输记录仅保留当前 SSH 会话，关闭后清空。

按用户要求，SSH 密码/私钥/口令与 AI API Key 在数据库中明文保存，管理员接口可读取；界面默认遮挡，点击显示图标可查看。这不是加密存储。数据库权限0600、数据目录0700，应用安装包不包含用户凭据。备份或迁移应针对数据库及其WAL状态进行一致性处理，不能只复制旧 JSON 文件。

原生应用通过统一网关 Unix Socket `/app/deskicons/` 提供服务，不监听公开 TCP 端口；管理请求校验 `X-Trim-Isadmin: true`，写请求校验会话令牌。SSH、设备及工作区按账号隔离。Docker和入口安装需要当前设备特权，应用以 root 运行；SSH终端仍使用指定目标账号。

详细表结构和升级策略见 [SQLite存储说明](sqlite-storage.md)，后端结构及实机验收见 [架构记录](backend-architecture.md)。

## 开发与检查

```sh
npm ci
npm run build
npm start
```

访问 `http://127.0.0.1:5178/app/deskicons/`。可设置 `PORT`、`DATA_DIR`、`DOCKER_SOCKET`；本地与原生数据目录需隔离。本地Docker不可用时返回真实错误，不使用演示容器。

```sh
npm test
npm run lint
npm run typecheck
npm run format:check
```

`npm test` 会先编译后端及独立的 `.web-test` 前端测试产物。前后端业务源码全部使用 TypeScript strict；前端不保留 JavaScript 兼容实现，动态界面由 React 渲染，浏览器、xterm、焦点和测量通过有类型的适配层接入。`npm run typecheck` 覆盖全部业务源码，并检查静态页面元素契约与 AST 约束，禁止显式 any、类型忽略注释及动态 HTML 拼接（仅隔离的 Markdown 消毒模板例外）。构建与打包也会执行该检查。浏览器和 Node 的 ESLint 环境分别配置。

不要同时运行清空/重建 `server/` 的构建命令与依赖该目录的测试或打包。多任务验证时应先完成构建，再运行只读检查。

## 打包和更新

准备官方 `tools/fnpack` 和脚本要求的 Linux CLI 归档，执行：

```sh
npm run pack
```

该命令顺序编译后端、构建前端、安装目标Linux依赖并生成 `build/deskicons/<版本号>.fpk`。当前只发布经实机验证的 Linux x86_64 包，依赖归档与CLI二进制由打包脚本核对 SHA-256，第三方声明位于 `third-party/`。

未安装时可在飞牛应用中心手动安装FPK。既有NAS按项目约定通过SSH停止正在运行的依赖入口和主应用、替换运行产物、依次恢复启动，保留数据目录；不使用可能卸载数据的 `install-local` 升级路径。`install-fpk` 对已安装应用可能只返回“is installed”，不能据此认定升级成功；只替换运行文件也不会更新应用中心登记版本。

每次更新核对实际API运行版本、服务状态、数据库完整性/外键、数据行数及关键接口。运行版本和应用中心登记版本应分别记录。密码不写入文档。

安装和更新脚本会检查并沿用已有 SQLite，执行支持的 schema 迁移；发现损坏时停止，不创建空库覆盖。卸载时通过飞牛应用中心向导选择“保留数据”或“删除全部应用数据”，默认保留；同一存储空间重新安装后继续使用。删除仅清理本应用的配置、数据和应用用户目录，不影响扫描目录中的文件、远程文件或Docker容器。原有独立桌面入口需另行管理。带卸载向导的包在当前NAS上需通过Web UI卸载，不能仅凭CLI退出码认定成功。详见[生命周期与数据保留](integrations/application-lifecycle.md)。
